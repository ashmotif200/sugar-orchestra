## Documents d'atelier (conservés tels quels)

Ces documents racontent le travail réel, y compris les impasses. Ils sont utiles pour
comprendre *pourquoi* le projet est dans cet état, et dangereux si on les lit comme une
description du produit actuel.

| Dossier | Contenu |
|---|---|
| [`admin/`](admin/) | exploitation et conception du Super Admin |
| [`phase-a/`](phase-a/) | mesures des références musicales, capacités du corpus, sélection des sons, rapports de phase |
| [`music-engine-v2/`](music-engine-v2/) | architecture des moteurs V2, profils musicaux, stratégie de transformation, changement de politique |
| [`v2.0.5/`](v2.0.5/) | analyse événementielle des trois références, modèles de style |
| [`v2.1/`](v2.1/) | équilibrage audio du moteur V2.1 |
| [`strategie/`](strategie/) | diagnostic de l'échec du morceau étalon, plan du morceau, réévaluation musicale |
| [`catalog/`](catalog/) | archivage non destructif du catalogue de 40 sons |
| [`production/`](production/) | script et mesures du morceau produit à la main |
| [`qr/`](qr/) | les huit QR (PNG, SVG), la planche imprimable, le tableau de correspondance |
| [`captures/`](captures/) | captures d'écran de l'application |

**Attention** : plusieurs documents d'atelier décrivent des états antérieurs
(« le catalogue publié reste celui des 40 sons », « publication non effectuée », etc.).
La description de l'état courant est le [README](../README.md) et
[HANDOVER.md](HANDOVER.md).
